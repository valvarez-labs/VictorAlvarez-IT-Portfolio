XML Schema Definition · Exercicis 1–3

Validació XML amb XSD
— Biblioteca

Com funciona biblioteca.xsd, per a quin problema serveix cada restricció i com detecta errors xmllint.

Exercici 1

Esquema base — biblioteca.xsd

L'objectiu és definir l'estructura que ha de complir qualsevol biblioteca.xml vàlid. L'XSD descriu quins elements i atributs existeixen, en quin ordre apareixen i de quin tipus han de ser.

biblioteca.xsd — versió exercici 1 
<?xml version="1.0" encoding="UTF-8"?>
<xs:schema xmlns:xs="http://www.w3.org/2001/XMLSchema">

  <xs:element name="biblioteca">
    <xs:complexType>
      <xs:sequence>

        <!-- Un o més <llibre> -->
        <xs:element name="llibre" maxOccurs="unbounded">
          <xs:complexType>
            <xs:sequence>
              <xs:element name="titol" type="xs:string"/>
              <xs:element name="autor"  type="xs:string"/>
              <xs:element name="any"    type="xs:integer"/>
              <!-- preu: decimal positiu (exercici 1) -->
              <xs:element name="preu">
                <xs:simpleType>
                  <xs:restriction base="xs:decimal">
                    <xs:minExclusive value="0"/>  <!-- no permet 0 ni negatius -->
                  </xs:restriction>
                </xs:simpleType>
              </xs:element>
            </xs:sequence>
            <!-- isbn: atribut obligatori -->
            <xs:attribute name="isbn" type="xs:string" use="required"/>
          </xs:complexType>
        </xs:element>

      </xs:sequence>
    </xs:complexType>
  </xs:element>

</xs:schema>

Decisió clau — per a preu usem <xs:simpleType> en lloc de type="xs:decimal" directament, perquè necessitem afegir una restricció. Si posem un tipus senzill sense límits, acceptaria valors negatius o zero.

Element / Atribut Decisió i motiu
<xs:sequence> Obliga que els fills apareguin en ordre exacte: titol → autor → any → preu. Si canviessin d'ordre l'XML seria invàlid.
maxOccurs="unbounded" Permet qualsevol nombre de llibres (≥ 1, perquè minOccurs per defecte és 1).
type="xs:integer" L'any ha de ser un número enter (no s'accepta "2024.5").
xs:minExclusive value="0" El preu ha de ser estrictament major que 0. S'usa minExclusive (no minInclusive) per excloure el 0 mateix.
use="required" Sense isbn, l'element <llibre> és invàlid. No existeix un valor per defecte.
Exercici 2

Restricció de rang per a preu

Afegim dos facets de restricció per delimitar el rang del preu: mínim 0.01 € i màxim 999.99 €. Substituïm la restricció anterior per la versió ampliada:

fragment de biblioteca.xsd — restricció preu (ex. 2) 
<xs:element name="preu">
  <xs:simpleType>
    <xs:restriction base="xs:decimal">
      <xs:minInclusive value="0.01"/>   <!-- ≥ 0.01 (inclòs) -->
      <xs:maxInclusive value="999.99"/> <!-- ≤ 999.99 (inclòs) -->
    </xs:restriction>
  </xs:simpleType>
</xs:element>

Per què minInclusive i no minExclusive? Perquè 0.01 ja és el valor mínim acceptable; volem incloure'l. Si usàvem minExclusive="0.01", el valor mínim seria 0.02 (o 0.011…), cosa que no coincidiria amb l'enunciat.

La taula resum dels quatre facets numèrics principals en XSD:

Facet Significat
xs:minInclusive Valor mínim inclòs (≥)
xs:minExclusive Valor mínim exclòs (>)
xs:maxInclusive Valor màxim inclòs (≤)
xs:maxExclusive Valor màxim exclòs (<)
Exercici 3

Validar amb un preu negatiu — error de xmllint

Modifiquem el biblioteca.xml posant un preu negatiu per veure com reacciona el validador:

biblioteca.xml — valor invàlid intencionat 
<biblioteca>
  <llibre isbn="978-84-376-0494-7">
    <titol>Don Quijote de la Mancha</titol>
    <autor>Miguel de Cervantes</autor>
    <any>1605</any>
    <preu>-5.99</preu>  <!-- ← valor invàlid! -->
  </llibre>
</biblioteca>

Executem la validació amb la comanda:

terminal 
$ xmllint --schema biblioteca.xsd biblioteca.xml --noout

El missatge d'error que retorna xmllint és similar a:

biblioteca.xml:6: element preu: Schemas validity error :
Element 'preu': '-5.99' is not a valid value of the atomic type defined by restriction of 'decimal'.

Observa que l'error indica:

  • La línia exacta on es troba el problema (línia 6).
  • L'element afectat (preu).
  • El valor invàlid (-5.99) i per quin motiu: no compleix la restricció del simpleType basat en xs:decimal.

Si el document fos vàlid, xmllint no mostraria res (o mostraria biblioteca.xml validates).

Nota

Context — Quan s'usa XSD avui en dia?

XSD és verbós (com has vist, calen moltes línies per a una restricció senzilla), però segueix sent fonamental en tres àmbits:

Àmbit Per què XSD i no altres?
Banca / Assegurances / Adm. Pública XML és l'estàndard legal en molts països. Els formats com SEPA, eSAP o factura electrònica usen XSD per garantir interoperabilitat.
Serveis SOAP WSDL (la descripció d'un servei SOAP) integra XSD per definir els tipus dels missatges enviats i rebuts.
Configuracions crítiques Fitxers de configuració d'aplicacions corporatives (Maven, Spring, etc.) usen XSD per evitar errors de configuració en producció.

Alternativa moderna: Per a APIs REST i aplicacions web, s'utilitza JSON Schema (molt més concís) o llibreries com Zod (TypeScript) o Pydantic (Python). Aprendre XSD et dóna la base conceptual per entendre qualsevol sistema de validació d'esquemes.
